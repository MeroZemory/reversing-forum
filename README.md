# Reversing All

리버스 엔지니어링의 질문, 분석 과정과 AI 활용법을 함께 나누는 커뮤니티입니다.
카톡은 대화의 중심으로 두고, 웹에는 정리하고 검증해 다시 쓸 수 있는 정보를 쌓습니다.

## 지금 만드는 것

큰 틀은 **자유 커뮤니티 → 정리·검증한 지식 → AI 보조**입니다.
첫 구현은 비회원의 글 읽기와 회원의 가입·글 작성·댓글을 연결합니다.
등록한 글은 비공개로 저장하고 Jev 최소검수를 통과하면 공개합니다.
보류되거나 API 오류가 발생한 글은 작성자만 볼 수 있습니다.

위키, 상세 팩트체크, 회원이 호출하는 AI 댓글, 운영 도구는 [TODO.md](TODO.md)의 순서대로 추가합니다.
강의·실습·CTF는 후속 단계입니다. 세부 정책은 실제 흐름을 구현하며 필요할 때 결정합니다.

## 실행

Node.js 22.13 이상을 사용합니다.

```sh
npm install
```

`.env.example`을 `.env`로 복사하고 `BETTER_AUTH_SECRET`을 임의의 긴 값으로 설정합니다.
다음 명령으로 값을 생성할 수 있습니다. 생성한 값은 `.env`에만 보관합니다.

```sh
node -e "console.log(require('node:crypto').randomBytes(48).toString('base64'))"
npm run db:init
npm run dev
```

기본 주소는 `http://127.0.0.1:3000`입니다. `BETTER_AUTH_URL`도 같은 주소를 사용합니다.
현재 작업 환경에는 무작위 세션 비밀값을 가진 로컬 `.env`를 준비했습니다.

Jev 인증은 `TYPESAFE_API_KEY` 또는 `TYPESAFE_KEY_FILE`로 설정합니다.
키 파일의 기본 예시는 `C:/_authentication/typesafe-jev-api-key.txt`입니다.
키가 없거나 API가 실패하면 글은 공개되지 않습니다. 비밀값을 저장소에 넣지 않습니다.

SQLite는 로컬 반복 개발을 위한 저장소입니다. 운영 DB와 호스팅은 배포를 준비할 때 결정합니다.
현재 회원가입은 이메일·비밀번호로 동작하며, 이메일 인증·계정 복구는 공개 운영 전 TODO입니다.

## 폴더

```text
src/
  app/          페이지와 HTTP 진입점
  components/   화면 구성 요소
  server/       인증, 저장, 커뮤니티 동작, Jev 연동
  lib/          공통 타입과 표시 도구
scripts/        DB 초기화와 검증 도구
tests/          서버 테스트와 브라우저 테스트
legacy/         이전 구현을 원형 그대로 보존한 참고 자료
```

별도 API 서버나 여러 서비스로 나누지 않고 단일 Next.js 앱으로 시작합니다.
회원 세션은 [Better Auth](https://better-auth.com/docs/integrations/next)를 사용합니다.
원본 카톡 백업은 로컬 요구 분석 자료이며 검색 가능한 대화 아카이브로 제공하지 않습니다.

## 검증

```sh
npm run typecheck
npm test
npm run test:e2e
npm run build
```

브라우저 테스트는 별도 DB에서 헤드리스로 실행하며 실제 Jev 호출 대신 테스트 응답을 사용합니다.
첫 화면의 중복 동선, 320·390·1440px 화면의 계정 접근과 터치 영역, 탭·검색 시 스크롤 유지도 확인합니다.
브라우저 확장이 문서 루트에 붙이는 외부 속성은 `<html>`에서만 허용하며, 본문의 hydration 불일치는 계속 감지하는 회귀 테스트를 둡니다.
필요하면 `npx playwright install chromium`으로 테스트 브라우저를 설치합니다.
`JEV_MOCK`은 개발·테스트에서만 사용하고 운영 모드에서는 무시합니다.
실제 Jev 검수 기준의 정확도는 별도 평가가 필요합니다. 현재 기준은 확정된 운영 정책이 아닙니다.

게임 보안 연구 기능의 제공 범위는 [법률 검토 문서](docs/game-security-legal-review.md)에 정리했습니다.
개별 콘텐츠의 합법성 판정이나 자동 제재 정책을 확정한 문서는 아닙니다.

게시판을 나눌지와 글의 목적·주제로 찾아보는 방식은 [포럼 구조 조사](docs/research/forum-organization-20261001/report.md)에서 비교합니다.
현재 유형 메뉴를 최종 분류로 확정한 상태는 아닙니다.

## 화면 구성

밝은 분석 도구를 기준으로 짙은 헤더, 회색 바탕, 얇은 구분선과 작은 모서리를 사용합니다.
브랜드는 헤더에서 한 번 표시하고, 첫 화면의 제목은 최신 글이나 선택한 글 유형을 나타냅니다.
한국어 본문은 일반 글꼴, 영문 브랜드·날짜·댓글 수·태그는 고정폭 글꼴을 사용합니다.

색상·글꼴·간격·모서리·크기는 `src/app/tokens.css`에서 관리합니다.
버튼과 이동 링크는 `src/components/ui/action.tsx`, 글 유형 표시는 `kind-badge.tsx`를 재사용합니다.
목록·가입·작성·읽기·댓글의 화면 스타일은 `src/app/globals.css`에서 이 토큰을 사용합니다.

브랜드는 Reversing All입니다. 각 글자가 곡선으로 이동하며 앞·뒷면을 넘기고, 전체 이름의 뒤집힘과 복귀가 8.4초 루프로 이어집니다.
기본 이름은 한 주기에서 약 5초간 읽히며, 작은 글자 움직임과 선 강조가 이어집니다. OS 동작 줄이기 설정과 관계없이 같은 연출을 재생합니다.
왼쪽 심벌을 누르면 전체 연출을 재생하거나 정지하며, 선택은 이 브라우저에 저장합니다. 이름을 누르면 홈으로 이동합니다.
제작 근거와 검토 방법은 [로고 연출 기록](docs/research/brand-motion-20261002.md)에 정리했습니다.
