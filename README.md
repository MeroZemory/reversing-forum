# Reversing All

리버스 엔지니어링의 질문, 분석 과정과 AI 활용법을 함께 나누는 커뮤니티입니다.
카톡은 대화의 중심으로 두고, 웹에는 정리하고 검증해 다시 쓸 수 있는 정보를 쌓습니다.

## 지금 만드는 것

큰 틀은 **자유 커뮤니티 → 정리·검증한 지식 → AI 보조**입니다.
첫 구현은 비회원의 글 읽기와 회원의 가입·글 작성·댓글을 연결합니다.
등록한 글은 비공개로 저장하고 Jev 최소검수를 통과하면 공개합니다.
보류되거나 API 오류가 발생한 글은 작성자만 볼 수 있습니다.

위키, 상세 팩트체크, 회원이 호출하는 AI 댓글, 운영 도구는 [TODO.md](TODO.md)의 순서대로 추가합니다.
강의·실습·CTF는 후속 단계입니다. 세부 정책은 실제 흐름을 구현하며 필요할 때 결정합니다.

## 실행

Node.js 22.13 이상을 사용합니다.

```sh
npm install
```

`.env.example`을 `.env`로 복사하고 `BETTER_AUTH_SECRET`을 임의의 긴 값으로 설정합니다.
다음 명령으로 값을 생성할 수 있습니다. 생성한 값은 `.env`에만 보관합니다.

```sh
node -e "console.log(require('node:crypto').randomBytes(48).toString('base64'))"
npm run db:init
npm run dev
```

기본 주소는 `http://127.0.0.1:3000`입니다. `BETTER_AUTH_URL`도 같은 주소를 사용합니다.
현재 작업 환경에는 무작위 세션 비밀값을 가진 로컬 `.env`를 준비했습니다.

Jev 인증은 `TYPESAFE_API_KEY` 또는 `TYPESAFE_KEY_FILE`로 설정합니다.
키 파일의 기본 예시는 `C:/_authentication/typesafe-jev-api-key.txt`입니다.
키가 없거나 API가 실패하면 글은 공개되지 않습니다. 비밀값을 저장소에 넣지 않습니다.

SQLite는 로컬 반복 개발을 위한 저장소입니다. 운영 DB와 호스팅은 배포를 준비할 때 결정합니다.
현재 회원가입은 이메일·비밀번호로 동작하며, 이메일 인증·계정 복구는 공개 운영 전 TODO입니다.

## 폴더

```text
src/
  app/          페이지와 HTTP 진입점
  components/   데이터·이벤트를 받아 그리는 화면과 공통 UI
  features/     클라이언트 동작과 화면을 연결하는 진입점
  client/       API·인증 어댑터, 초안 저장과 동작 훅
  contracts/    서버와 화면 사이의 명시적인 데이터 계약
  server/       인증, 저장, 커뮤니티 동작, Jev 연동
  lib/          공통 타입과 표시 도구
scripts/        DB 초기화와 검증 도구
tests/          서버 테스트와 브라우저 테스트
legacy/         이전 구현을 원형 그대로 보존한 참고 자료
```

별도 API 서버나 여러 서비스로 나누지 않고 단일 Next.js 앱으로 시작합니다.
회원 세션은 [Better Auth](https://better-auth.com/docs/integrations/next)를 사용합니다.
원본 카톡 백업은 로컬 요구 분석 자료이며 검색 가능한 대화 아카이브로 제공하지 않습니다.

### 데이터와 화면의 경계

서버의 조회·세션·공개 권한 판단은 `server/`가 맡습니다. `server/screens.ts`는 저장소의 결과를 `contracts/screens.ts`에 정의한 화면 데이터로 준비합니다. 화면에는 SQL 행, 인증 SDK 응답, 이메일이나 Jev 검수 근거를 전달하지 않습니다. `app/`은 이 결과에 따라 이동·404·메타데이터를 처리하고 화면과 필요한 기능을 연결합니다.

`components/screens/`와 `components/`는 전달받은 데이터·상태·이벤트를 표시합니다. API 호출, 로그인 처리와 작성 초안 저장을 직접 수행하지 않습니다. 서버에서 그리는 화면에는 작성·댓글 같은 기능을 React 요소로 전달하고, 클라이언트의 `features/` 진입점은 동작 훅의 상태·이벤트를 화면에 전달합니다.

작성·댓글·인증 동작은 `client/hooks/`, HTTP·인증 구현은 `client/`의 어댑터에 모았습니다. UI를 바꾸려면 화면 컴포넌트·토큰·스타일을 바꾸고 같은 데이터와 이벤트 계약을 연결하면 됩니다. 화면 배치나 마크업 변경 때문에 DB·Jev·인증 API·초안 복원 로직을 다시 작성할 필요가 없습니다. UI에만 필요한 펼침·초점·비밀번호 표시·로고 재생과 스크롤 상태는 화면 계층에 둘 수 있습니다.

`tests/server/layers.test.ts`는 간접 import까지 확인해 화면의 서버·클라이언트 데이터 구현 의존과 서버의 화면 의존을 막습니다. `screens.test.ts`는 세션 정보의 최소 전달, 작성자 조회, 비공개 데이터 처리와 복귀 문맥을 검증합니다. 서버 쓰기의 권한·입력 검증과 공개 전 검수는 계속 서버에서 수행합니다.

## 검증

```sh
npm run typecheck
npm test
npm run test:e2e
npm run review:ui
npm run build
```

브라우저 테스트는 별도 DB에서 헤드리스로 실행하며 실제 Jev 호출 대신 테스트 응답을 사용합니다.
첫 화면의 중복 동선, 320·390·1440px 화면의 계정 접근과 터치 영역, 탭·검색 시 스크롤 유지도 확인합니다.
브라우저 확장이 문서 루트에 붙이는 외부 속성은 `<html>`에서만 허용하며, 본문의 hydration 불일치는 계속 감지하는 회귀 테스트를 둡니다.
필요하면 `npx playwright install chromium`으로 테스트 브라우저를 설치합니다.
`JEV_MOCK`은 개발·테스트에서만 사용하고 운영 모드에서는 무시합니다.
실제 Jev 검수 기준의 정확도는 별도 평가가 필요합니다. 현재 기준은 확정된 운영 정책이 아닙니다.

게임 보안 연구 기능의 제공 범위는 [법률 검토 문서](docs/game-security-legal-review.md)에 정리했습니다.
개별 콘텐츠의 합법성 판정이나 자동 제재 정책을 확정한 문서는 아닙니다.

게시판을 나눌지와 글의 목적·주제로 찾아보는 방식은 [포럼 구조 조사](docs/research/forum-organization-20261001/report.md)에서 비교합니다.
조사 결과를 바탕으로 이번 구현은 하나의 글 목록과 질문·공유·자유 목적 필터를 사용합니다.

## 화면 구성

화면의 기준은 **공개 글 찾기 → 읽고 댓글로 참여하기 → 질문·자료 남기기 → 내 글의 공개 상태 확인하기**입니다.
첫 화면에 글 목록과 검색을 두고, 글의 목적은 질문·공유·자유로 좁힙니다. AI·도구·환경은 독립 게시판이 아닌 주제 태그입니다.
기존 분석·AI 활용 분류의 글은 공유 필터에서 함께 찾으며, 저장된 분류·주소·댓글은 바꾸지 않습니다.
주제는 본문 검색과 구별되는 정확한 태그 조건입니다. 목적·주제·검색어·페이지가 URL에 남고, 목록에서 들어간 글의 복귀 링크는 읽던 조건과 위치를 복원합니다.

| 화면            | 가장 중요한 행동                   | 배치와 문구의 기준                                                                                                                                  |
| --------------- | ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 글 목록         | 읽거나 답할 글 찾기                | 목록·검색·목적 필터를 먼저 보여 주고, 공개 글의 실제 총수와 페이지를 표시합니다. 주제는 데스크톱 오른쪽, 모바일에서는 검색 아래 펼침 메뉴에 둡니다. |
| 글 읽기         | 분석 과정 이해하고 댓글로 참여하기 | 읽기 폭을 제한하고 본문·코드·주제·사람의 댓글 순서로 읽게 합니다. 댓글 바로가기로 긴 글의 대화에 접근합니다.                                        |
| 글 쓰기         | 목적에 맞게 질문·자료 남기기       | 질문·공유·자유를 고르면 안내가 달라집니다. Markdown 미리보기와 회원별·탭별 초안 복원을 제공하고, 기본 확인 후 공개되는 흐름을 설명합니다.           |
| 내 글           | 내가 쓴 글의 공개 상태 확인하기    | 공개·공개 전 확인·공개 보류를 구분합니다. 보류를 검증 완료나 진행 중인 검수로 표현하지 않습니다.                                                    |
| 로그인·회원가입 | 하려던 작성·댓글 이어가기          | 로그인 이유와 복귀 위치를 연결합니다. 비밀번호 표시, 입력 조건, 실패 안내와 키보드 초점을 제공합니다.                                               |
| 404·오류        | 읽기 흐름으로 복귀하기             | 주소 확인·목록 이동·내 글 확인 또는 재시도를 제공합니다. 비공개 글의 존재나 내용을 드러내지 않습니다.                                               |

짙은 헤더와 회색 바탕, 얇은 구분선으로 글과 도구 화면의 구조를 구별합니다. 주요 행동에는 녹색, 질문에는 파란색, 공개 전 확인에는 황색, 공개 보류에는 적색을 사용합니다.
공개 상태는 콘텐츠의 정확성을 인증하는 표시가 아닙니다. 브랜드는 헤더에서 한 번 표시합니다.
한글 본문과 입력에는 로컬 가변 글꼴 [Pretendard](https://github.com/orioncactus/pretendard)를 사용하며, 글꼴과 SIL OFL 라이선스는 `src/app/fonts/`에 함께 보관합니다. 브랜드·코드·날짜·태그에는 고정폭 글꼴을 사용합니다.

색상·글꼴·간격·모서리·크기는 `src/app/tokens.css`에서 관리합니다.
버튼·이동 링크, 목적 표시, 주제 링크, 공개 상태와 안내문은 `src/components/ui/`의 컴포넌트를 재사용합니다.
목록·가입·작성·읽기·댓글의 화면 스타일은 `src/app/globals.css`에서 이 토큰을 사용합니다.

위키는 공동 편집·버전 관리가 필요할 때 별도 공간으로 나눕니다. AI 검증은 글 버전과 연결된 근거 영역, 호출 봇은 댓글 참여로 연결합니다. 강의·실습·CTF는 진도·제출·채점 흐름을 갖춘 별도 작업 공간으로 확장합니다. 현재 메뉴에는 동작하는 기능만 표시합니다.
화면 검수는 로컬 테스트 전용 DB에서 빈 목록·글이 쌓인 목록·필터·읽기·작성·가입·공개 상태·오류를 확인하며, 운영용 DB에 예시 글을 넣지 않습니다.
`npm run review:ui`는 66개 화면 조합의 캡처와 검수 결과를 `data/ui-ux/latest/`에 저장합니다. 저장소에는 원본 대화·계정·로컬 DB·검토 이미지가 포함되지 않습니다.

브랜드는 Reversing All입니다. 각 글자가 곡선으로 이동하며 앞·뒷면을 넘기고, 전체 이름의 뒤집힘과 복귀가 8.4초 루프로 이어집니다.
기본 이름은 한 주기에서 약 5초간 읽히며, 작은 글자 움직임과 선 강조가 이어집니다. OS 동작 줄이기 설정과 관계없이 같은 연출을 재생합니다.
왼쪽 심벌을 누르면 전체 연출을 재생하거나 정지하며, 선택은 이 브라우저에 저장합니다. 이름을 누르면 홈으로 이동합니다.
제작 근거와 검토 방법은 [로고 연출 기록](docs/research/brand-motion-20261002.md)에 정리했습니다.
