# 구현 지시: Reversing All 화면 개편 v1

작성: 2026-10-05 · 설계 담당(Claude, 설계 작업자) → 구현 담당(reversing-forum 메인 Codex 세션)
기준: [화면 설계서](design-system.md) · [IA](ia.md) · [질문 지도](feature-questions.md) · [목업](mockups/index.html)과 [치수표](mockups/README.md)
상태: **2026-10-05 사용자 구현 지시 반영.** 질문 1~8은 권장안을 되돌릴 수 있게 적용한다. 설계와 다르게 해야 할 이유가 생기면 설계서에 근거를 적고 바꾼다. 목업의 공개 330개는 당시 스냅샷이며, 실제 수용 검사는 검사 시점의 공개 글 전체를 대상으로 한다.

## 0. 먼저 지킬 것

- GOAL.md·AGENTS.md가 우선한다. 이번 개편은 **표시 계층**만 바꾼다.
  - 승인본 37개와 공개 330개의 **제목·본문 문자열을 바꾸지 않는다.** 편집자 보충 상자·출처 목록·코드 머리줄은 렌더러가 만든다.
  - 출처 설명, 삭제·이의 요청, 글 신고 경로, 치트 배포 경계 문구, 보류 글 작성자 전용 조회, 비공개 글 미집계를 유지한다.
  - 가상 회원·댓글을 만들지 않는다. 목업의 "예시"(보라 배지) 자료는 실제 앱에 넣지 않는다.
- 자료 가공 파이프라인(`src/server/chat-pipeline/`, `scripts/chat-*`)과 실행 중인 작업의 입력·증거 경로는 건드리지 않는다.
- 새 의존성 없이 구현한다(코드 강조는 정규식 기반 결정적 함수, 목업 `core.js`의 `hlLine`을 옮긴다).
- 작업 단위마다 typecheck · 관련 테스트 · 빌드 · 헤드리스 화면 검사 후 원자적으로 커밋한다(AGENTS.md).

### 단계 1. 토큰과 화면 색

- `src/app/tokens.css`: 설계서 §5 표대로 값을 바꾸고 새 토큰(`--color-meta`, `--color-border-strong`, `--color-mark`, `--color-warn(-soft)`, 코드 색 10개)을 더한다. 다크 값은 `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) {…} }`와 `:root[data-theme="dark"] {…}` 두 곳에 같은 값으로.

## 5. 위험과 주의

### 질문 1~8의 적용안

2026-10-05 사용자가 권장안 적용을 지시했다. 저장된 본문·태그와 기존 검색 노출 정책은 변경하지 않는다.

1. 화면 안내·빈 상태·오류는 해요체로 맞춘다. 편집 본문과 운영 안내의 법적 의미는 보존한다.
2. 내비 이름은 **주제**로, 주소는 `/resources`로 둔다.
3. **답을 기다리는 질문**을 전역 내비에 둔다.
4. 11개 별칭 묶음은 코드의 표시·조회 설정으로만 적용한다. 저장 태그는 그대로 둔다.
5. 기존 색인 정책을 유지한다. 필터 조합과 새 질문 목록은 `noindex, follow`로 시작한다.
6. 코드 블록 바탕은 화면 테마를 따른다.
7. 기본 화면 색은 시스템 설정을 따르고 바닥글에서 바꾼다.
8. 편집 자료 목록은 기록 시기로 구분하고, 글 화면에는 편집 계정 표시를 유지한다.

### 구현 중 확인한 조정

- 검색·글쓰기 버튼은 기존 접근성 검사와 작은 화면의 터치 기준을 유지하도록 높이 44px 이상으로 두었다. 검색 상자는 버튼을 담도록 46px이다.
- 본문 문자열을 여러 Markdown 입력으로 나누지 않고, 한 번 파싱한 문단을 보충 상자로 묶었다. 상자 밖에 정의된 출처 링크와 각주가 끊기지 않는다.
- 초기 질문 제목은 기존 등록 제한인 160자에 맞춘다. 저장한 초안이 있으면 초안을 우선한다.
- 예전 `/resources?q=…`와 필터 주소는 결과 목록으로 유지한다. 주제 색인의 새 헤더 검색은 `/`의 결과 목록으로 이동한다.
- 화면 색 초기화는 오류 복구 때 재실행 경고가 나지 않도록 작은 외부 스크립트로 둔다. `async`와 `blocking="render"`로 초기 색을 첫 렌더 전에 적용한다. [표준 속성 설명](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/script#blocking)

- 목록 표 → 줄 변경은 e2e가 많이 의존하는 화면이다. 접근 이름을 유지하고, `test-results/design-home-*.png` 비교는 새 기준으로 갱신한다.
- 검색 관련도 정렬은 페이지 이동 시 같은 순서가 유지되도록 마지막 정렬 키에 `p.id`를 둔다.
- 미리보기 평문화는 표시용이다. 중복 판정·Jev 입력·임베딩에 쓰는 본문을 바꾸지 않는다.
- 별칭 합치기는 공개 글만 센다. 보류·오류 글에만 있는 태그가 색인에 나오면 안 된다(기존 e2e `privateTag` 검사 유지).
- 다크 모드 인라인 스크립트는 저장값이 세 값 중 하나일 때만 적용하고, 나중에 CSP를 넣으면 nonce를 붙인다.
