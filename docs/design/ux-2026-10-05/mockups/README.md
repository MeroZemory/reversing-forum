상태: 2026-10-05 사용자 구현 지시를 받은 목업 기준 · 공개 330개는 당시 스냅샷
상위 문서: [화면 설계서](../design-system.md) · [IA](../ia.md) · [질문 지도](../feature-questions.md) · [구현 지시](../handoff.md)

## 여는 법

- `index.html`을 바로 연다(`file://`). 외부 CDN·글꼴 없음. 서버가 필요 없다.
- 위쪽 **검토용 툴바**는 앱 바깥이다(구현 대상 아님): 미리보기 390/768/1440, 라이트·다크, 비회원·회원, 상태(정상·회원 활동 있음(예시)·로딩·오류), 화면 바로가기.
- 주소 해시가 곧 전체 상태다: `index.html#size=pc&theme=dark&auth=member&state=active&go=post-q`
  - `go` = home, open, topics, guide, tag, search, search-empty, search-sheet, post-short, post-supp, post-prov, post-q, post-long, zoom, post-held, new, me
  - 앱 안에서 이동하면 `screen`, `id`, `q`, `tag`, `guide`, `purpose`, `page`, `prov`, `sheet`가 해시에 남는다. 해시는 목업 재현용이고, 실제 앱 주소는 설계서 §3(기존 `/`, `/?q=`, `/?tag=`, `/resources`, `/resources/[slug]`, `/posts/[id]` + 새 `/questions`).

## 구현 규칙

1. **토큰만**: 색은 `app.css` 맨 위(라이트·다크 쌍). 구현은 기존 `tokens.css` 이름에 대응(설계서 §5 표).
2. **반응형**: 목업의 `@container app`은 구현에서 `@media (min-width: 600px | 1024px)`.
3. **선택·펼침 상태**는 `aria-pressed` / `aria-current` / `aria-expanded`로만.
4. **목록 조건은 링크**: 칩·페이지는 기존처럼 `Link`로 주소를 바꾼다(`scroll={false}`). 목업의 `data-act`는 흉내다.
5. **본문 변환은 표시 단계에서만**: 편집자 보충 상자·출처 목록·코드 머리줄은 렌더러가 만든다. 저장된 본문·승인본 문자열은 바꾸지 않는다.
6. **클라이언트 코드는 최소로**: 복사·줄바꿈·바이트·출처 펼침·목차 현재 위치·화면 색만 클라이언트. 강조는 서버에서.
7. **접근 이름 유지**: 기존 e2e가 쓰는 "글 쓰기", "검색어 지우기", "모든 조건 지우기", "전체 글 보기", "글 신고·삭제 요청", "질문"·"공유"·"자유" 등.
8. **피할 장식**(설계서 §13).

## 확인 결과(Playwright, 2026-10-05)

- `file://`로 열어 17개 화면 × 390·768·1440 × 라이트·다크 × 비회원·회원 = 204조합, 여기에 기존 `review:ui`가 보는 **320폭** 68조합을 더해 **272조합**: 페이지 가로 넘침 0(코드·표·칩 줄의 내부 스크롤과 시트 겉면 제외), 콘솔·페이지 오류 0. 320폭에서는 회원 머리의 "내 글"을 계정 메뉴로 옮기고 코드 머리줄의 파일 설명을 숨긴다.
- 컨트롤과 결과(390×844): 목적 칩을 머리 바로 아래로 올린 뒤 "질문"을 누르면 칩·"공개 글 100개"·첫 줄이 모두 화면 안. 답 기다림 "IDA" 칩 → "#IDA 질문 11개" 화면 안. 주제 찾기 "패킹" 입력 → 입력칸(고정)과 결과(패킹 8 · 언패킹 3) 화면 안.
