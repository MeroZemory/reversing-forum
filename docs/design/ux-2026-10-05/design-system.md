# Reversing All 화면 설계서 v1

상태: 2026-10-05 사용자 구현 지시를 받은 설계 기준 · 대상: `src/` 단일 Next.js 앱의 공개 화면 전체
같이 읽을 것: [기능 배치 결정표](ia.md) · [기능별 질문 지도](feature-questions.md) · [목업과 치수표](mockups/README.md) · [구현 지시](handoff.md)

이 문서는 화면을 고치기 전에 "누구에게, 언제, 어느 기기에서, 무엇을, 얼마나 크게" 보여 줄지를 정한다. 구현은 이 문서와 목업을 따르고, 문서에 없는 배치·크기·문구를 더하지 않는다. 바꾸고 싶으면 문서부터 고친다.

## 1. 누가, 언제, 무엇을 하러 오는가

| 상황                                                              | 기기            | 머무는 시간 | 하고 싶은 일                          | 화면이 줘야 하는 것                                                      |
| ----------------------------------------------------------------- | --------------- | ----------- | ------------------------------------- | ------------------------------------------------------------------------ |
| 검색엔진·AI 검색에서 개념 질문으로 바로 글에 도착("PE Hint 서수") | PC·휴대폰       | 30초~2분    | 답을 읽고 믿어도 되는지 판단          | 첫 화면에 **답 본문**, 한 줄짜리 출처·시기, 공개 문서 출처 목록          |

| 원자료 당사자·독자, 가끔                                          | 아무 기기       | 1~2분       | 이 글이 어디서 왔는지, 정정·삭제 요청 | 글마다 "출처와 확인" 펼침, 정정·삭제 요청 경로                           |

결론

- **목록 = 답을 훑는 곳.** 짧은 답은 목록에서 끝까지 읽힌다. 제목 아래 답 3줄, 기록 시기, 주제 3개만 둔다.
- **글 = 믿고 가져가는 곳.** 답 → 편집자 보충(출처) → 같은 주제 글 → 답변·댓글 순서. 출처 고지는 펼침 하나로 접는다.
- **질문 100개는 비어 있는 자리가 아니라 참여의 입구다.** 답 없는 질문을 따로 모아 첫 화면 내비게이션에 둔다.
- **긴 기술 글은 아직 없지만 곧 온다.** 코드·디스어셈블리·표·그림 규칙을 지금 정해 둔다(§8). 목업의 긴 글은 "예시"로 표시했다.

## 2. 설계 원칙 (우선순위 순)

1. **답이 주인공.** 목록과 글 모두 질문에 대한 답 문장이 제목 다음으로 크고 먼저 보인다. 고지·메타는 답보다 작고 뒤에 온다.
2. **반복되는 것은 정보가 아니다.** 모든 줄에 같은 값(작성자 "자료편집", "댓글 0", 같은 날짜)이면 줄에서 뺀다. 다를 때만 보인다. 편집 자료와 회원 글의 구분은 "2017년 10월 카톡 기록"과 "회원 이름 · n일 전"이라는 서로 다른 메타로 유지한다.
3. **출처는 숨기지 않되 접는다.** 기록 시기는 항상 한 줄로 보이고, 기록 시점·웹 게시일·확인 내역·정정 경로는 "출처와 확인" 한 번 눌러 펼친다. 공개 문서로 덧붙인 내용은 본문 안에서 **편집자 보충** 상자로 구분하고 그 아래 출처를 번호 목록으로 둔다.
4. **코드는 코드답게.** 고정폭, 가로 스크롤(줄바꿈은 선택), 복사, 언어·파일 표시, 강조 줄, 디스어셈블리 주소·바이트 열을 흐리게. 본문 글꼴과 섞지 않는다. 주제·날짜에는 고정폭을 쓰지 않는다.
5. **찾던 맥락을 잃지 않는다.** 목적·주제·검색어·페이지를 주소에 두고, 글에서 돌아오면 같은 조건과 위치로 간다(기존 `FeedScrollRestoration` 유지). 조건을 바꾸는 칩은 결과 목록 바로 위에 붙인다(컨트롤과 결과가 한 화면).
6. **비어 있는 것은 다음 행동으로.** 검색 결과 없음 → "이 내용으로 질문하기", 답 없음 → "답 쓰기", 주제 없음 → 본문 검색.
7. **장식 대신 내용.** 색 띠, 제목 앞 아이콘 반복, 이모지, 그라데이션, 같은 정보의 삼중 강조, 검정 채움 칩을 쓰지 않는다(§13).

## 3. 정보 구조

전역 내비게이션(`nav aria-label="사이트 둘러보기"`, 기존 이름)은 셋이다. 4번째를 만들지 않는다.

| 이름                   | 주소              | 목적                        | 지금 화면과의 관계                                                                             |
| ---------------------- | ----------------- | --------------------------- | ---------------------------------------------------------------------------------------------- |
| **최신 글**            | `/`               | 새로 올라온 글·활동을 훑기  | 기존 그대로. 표 → 답 미리보기 줄                                                               |
| **답을 기다리는 질문** | `/questions` (새) | 답할 수 있는 질문 찾기      | 새 화면. 목적=질문 ∧ 댓글 0 인 공개 글                                                         |
| **주제**               | `/resources`      | 길잡이와 주제 색인으로 찾기 | 기존 "자료 길잡이"를 이름만 "주제"로 넓힘. 오른쪽 주제 목록·"주제별로 찾기" 펼침은 여기로 옮김 |

- 검색은 내비게이션 항목이 아니라 머리의 입력칸(PC·태블릿)과 돋보기 버튼(휴대폰)이다. 결과 주소는 기존 `/?q=`.
- 주제 하나의 글 목록: 태그는 기존 `/?tag=`, 길잡이는 기존 `/resources/[slug]`. 표기만 다른 태그는 합쳐 보인다(§7.4).
- 글 쓰기는 머리 오른쪽(PC)과 목록 머리(휴대폰)의 주 버튼 하나. 내 글·계정은 기존 위치.
- 바닥글: 운영 안내 · 삭제·이의 요청 · 화면 색(시스템·밝게·어둡게).

## 4. 반응형 규칙

| 구간     | 폭       | 배치                                                                                                | 머리                                                              |
| -------- | -------- | --------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| Compact  | < 600    | 1열, 좌우 여백 16                                                                                   | 56 · 로고 + 검색 버튼 + 로그인(또는 내 글·계정). 아래 내비 3칸 46 |
| Medium   | 600–1023 | 1열, 내용 최대 720 가운데, 여백 24                                                                  | 56 · 로고 + 검색칸 + 계정. 아래 내비 3칸                          |
| Expanded | ≥ 1024   | 셸 최대 1200, 여백 32. 목록 = 본문 760 + 오른쪽 300(간격 48). 글 = 읽기 폭 720(+ 목차 220, 간격 56) | 64 · 로고 + 내비 3개 + 검색칸(최대 440) + 글 쓰기 + 계정          |

- 머리는 모든 구간에서 상단 고정, 아래 내비(Compact·Medium)는 고정하지 않는다(읽는 공간 확보).
- 읽기 폭 720px은 본문 16px 한글 기준 한 줄 약 42~45자다. 코드 블록·표도 같은 폭 안에서 가로로 스크롤한다(본문 폭을 넘겨 튀어나오지 않는다).
- 글 화면의 목차는 Expanded에서 머리글(h2)이 3개 이상일 때만 오른쪽에 붙고, 좁은 폭에서는 제목 아래 접힌 "목차 n"이 된다.
- 가로 넘침 0: 390·768·1440 모든 화면에서 페이지 가로 스크롤이 없어야 한다(코드·표 내부 스크롤은 허용).

## 7. 화면별 배치

### 7.1 최신 글 `/`

- 머리 → (좁은 폭) 내비 → 제목 "최신 글" + 한 줄 소개 "리버싱 질문과 답을 모았어요. 과거 카톡 기록을 정리한 편집 자료와 회원 글이 함께 있어요." + (좁은 폭) 글 쓰기 → 목적 칩 → "공개 글 330개 · 최신순" → PostRow 30개 → 페이지 이동.
- Expanded 오른쪽: 답을 기다리는 질문 5개 · 주제 상위 14개(합친 개수) · 무엇을 나누나요(세 줄).
- 회원 활동이 생기면(기존 `compactEditorial` 규칙 그대로): 위에 "새로 정리한 편집 자료" 묶음(3개 + 주제별로 보기), 아래 "회원 글과 댓글이 있는 글 n개 · 최근 활동순".
- 기존 "주제별로 찾기" 펼침(좁은 폭)과 오른쪽 주제 전체 목록은 없앤다 → 주제 화면.
- 적용한 조건(주제·검색어)은 기존 `active-filters` 칩과 문구("검색어 지우기", "주제 지우기", "모든 조건 지우기")를 유지한다.

PostRow 내용

- 1줄: 목적 라벨 + (질문이면) "답 기다림" 또는 "답변 n".
- 제목: 2줄까지.
- 답 미리보기: 본문의 **기록 부분**(편집자 보충 앞)을 평문으로 3줄까지. 인라인 코드는 코드 모양 유지. 질문 글은 질문 본문.
- 메타: 편집 자료 = "2017년 10월 카톡 기록", 회원 글 = "이름 · 3일 전". 그 뒤 주제 3개(+n), 보충이 있으면 "보충 출처 n", 공유·자유 글에 댓글이 있으면 "댓글 n".

### 7.2 답을 기다리는 질문 `/questions`

- 제목 "답을 기다리는 질문" + "답이 아직 없는 질문이에요. 아는 내용이 있으면 짧게라도 남겨 주세요. 한 줄 답도 다음 사람에게 도움이 돼요."
- 주제 칩(질문에 많이 붙은 8개 + 전체) → "답을 기다리는 질문 100개 · 최신순" → PostRow + 오른쪽(또는 아래) "답하기" 버튼 → 글의 답변 쓰기로 이동(`#answers`).
- 대상: 공개 ∧ 목적=질문 ∧ 댓글 0. 답이 달리면 목록에서 빠진다.
- 오른쪽 상자에서 "답을 기다리는 질문"은 숨긴다.

### 7.3 주제 `/resources`

- 제목 "주제" + "운영자가 고른 길잡이로 시작하거나, 글에 붙은 주제로 찾아보세요."
- **길잡이**(구역 제목 옆: "운영자가 공개 글을 확인하고 묶었어요 · 정확성 인증 목록은 아니에요"): 기존 4개(학습 시작 13 · 실행 파일 분석 116 · 시스템과 네트워크 12 · 모바일과 펌웨어 9), 카드마다 대표 글 3개와 "○○ 글 모두 보기".
- **모든 주제 n개**: 상단 고정 입력칸 "주제 이름 찾기" → 바로 아래 주제 색인(개수 많은 순). 처음에는 2번 이상 쓰인 주제만, "한 번만 쓰인 주제 n개 더 보기". 입력하면 전체에서 거른다. 아래 한 줄: "표기만 다른 주제는 합쳐 보여요: 리버스 엔지니어링·역공학 → 리버싱, … 글에 붙은 원래 표기는 그대로 둬요."
- 없는 주제를 입력하면 "‘○○’ 주제가 없어요. 글 본문에서 찾기 ›".

### 7.4 주제 하나 `/?tag=` · 길잡이 `/resources/[slug]`

- "‹ 주제" → 제목(`#리버싱` 또는 길잡이 이름) → 설명. 합친 주제면 "‘리버스 엔지니어링’·‘역공학’으로 붙은 글도 함께 보여요."
- 목적 칩(이 주제 안 개수) → "#리버싱 글 45개 · 최신순" → PostRow. 결과 없음: "이 조건에 맞는 글이 없어요" + "조건 지우기".

### 7.5 검색 `/?q=`

- 좁은 폭은 본문 맨 위에 검색칸(현재 검색어), 넓은 폭은 머리 검색칸에 검색어.
- 제목 "‘IAT’ 검색 결과" + "제목·본문·주제에서 찾았어요."
- 검색어가 주제 이름과 같으면 맨 위 한 줄: "#IAT 주제 글 7개 모두 보기 ›".
- 목적 칩 → "검색 결과 8개 · 관련도순" → PostRow(제목·미리보기의 일치 부분 `<mark>`, 미리보기는 첫 일치 주변).
- 결과 없음(예: 실제로 0개인 "Ghidra"): "‘Ghidra’에 맞는 글이 아직 없어요" + "다른 표기나 더 넓은 말로 찾아보세요. 그래도 없다면 질문으로 남겨 주세요." + [‘Ghidra’로 질문하기](제목 채운 글쓰기) [모든 주제 보기] + 자주 찾는 주제.

- "같은 주제의 글": 이 글과 주제가 겹치는 공개 글 3개. 드물게 쓰인 주제가 겹칠수록 앞(§9 참고). "함께 읽을 글"(중복 판정이 확인한 연결)이 있으면 그것을 먼저 두고 같은 글은 빼서 중복을 없앤다.

### 7.7 글 쓰기 `/new` (기존 흐름 유지 + 보강)

- 목적 3칸("어떤 도움이나 반응을 원하나요?") → 목적별 안내 한 줄 → 제목 → **비슷한 글이 있어요 · 먼저 확인해 보세요**(제목 낱말로 공개 글 검색 상위 3, 막지 않음) → 본문: 머리글 오른쪽에 작성·미리보기 전환, 입력칸 위에 [코드][디스어셈블리][표][링크] 넣기 → "코드·디스어셈블리는 버튼으로 넣거나 ```로 감싸요. 이미지 첨부는 준비 중이에요." → 주제(최대 5, 입력 중 기존 주제 제안·표기 합침 안내 "‘윈도우’는 Windows 주제로 붙어요") → 공개 전 안내 + 등록.
- 검색 결과 없음에서 왔으면 목적=질문, 제목=검색어로 채운다.
- 초안 저장·복원·로그인 복귀는 기존 `use-post-composer` 그대로.

### 7.8 내 글 `/me` · 작성자 전용 글

- 상태 칩 전체·공개·확인 중·공개 보류(기존 `status`) → 줄: 목적 라벨 + 상태 단어, 제목, 날짜·답변 수.
- 공개 보류 글: 맨 위 Notice "공개 보류 · 나에게만 보여요" + 기존 사유 문구(해요체) + 관련 공개 글 + [수정하기][다시 확인 요청](기존 재시도·검토 요청 조건 그대로). 확인 중: "확인 중 · 나에게만 보여요 / 기본 확인이 끝나면 공개돼요."

## 8. 기술 글 읽기 규칙

현재 공개 글에는 코드 블록·표·그림이 없지만, 회원 글·위키·편집자 보충이 늘면 가장 자주 읽힐 요소다. 목업의 "x64 호출 규약으로 main의 인자를 따라가 보기"(예시)로 모든 규칙을 확인한다.

1. **인라인 코드**: 고정폭 0.875em, 옅은 바탕, 모서리 4, 좌우 5. 한 줄을 넘는 식별자는 칸 안에서 끊는다.
2. **코드 블록 머리줄**: 언어 이름(한국어 표기: "C", "x86-64 디스어셈블리", "명령") · 펜스의 `title="..."`(파일·구역·"설명용으로 정리" 같은 설명) · 오른쪽 버튼. 언어가 없으면 "텍스트".
3. **가로 스크롤이 기본**: 디스어셈블리·로그는 줄바꿈하면 열이 무너진다. "줄바꿈"을 켜면 이어지는 줄을 들여쓴다. 상태는 블록마다 따로, 저장하지 않는다.
4. **복사**: 블록 전체 원문(주소 포함)을 복사하고 버튼 글자를 "복사했어요"로 1.8초 바꾼다. 실패하면 "복사하지 못했어요".
5. **디스어셈블리**(펜스 `disasm`): 한 줄 = 주소 · 바이트 · 명령 · 피연산자 · `; 주석`. 주소·바이트·주석은 흐리게, 명령은 굵게. 라벨 줄(`main:`)은 본문색 굵게. 바이트 열은 Compact에서 처음 숨김("바이트" 버튼으로 켬), Medium 이상은 보임. 강조 줄은 바탕 + 왼쪽 3px 강조색 한 신호만.
6. **어셈블리**(펜스 `asm`): 주소 없이 명령·피연산자·주석 강조.
7. **C·C++·Python**: 키워드·문자열·숫자·함수·주석 5종만 색. 5줄 이상이면 줄 번호(선택 안 됨).
8. **명령**(펜스 `shell`): 프롬프트(`>`·`$`)는 흐리게·복사 제외 표시, 옵션(`/O1`)은 키워드색.
9. **표**: 가로 스크롤 상자 안. 첫 열 고정, 머리 줄 옅은 바탕, 숫자 열 오른쪽 정렬(`---:`), 칸 안 코드는 인라인 코드. 28자를 넘는 설명 칸은 줄바꿈.
10. **그림**: 본문 폭에 맞춰 보이고 누르면 크게. 설명은 아래 한 줄. 외부 이미지 자동 로드는 지금처럼 하지 않는다(업로드 기능 이후 같은 출처만).
11. **편집자 보충**: 본문 머리글이 정확히 "편집자 보충"이면 그 머리부터 다음 같은 수준 머리글 전까지 상자로 묶는다. 상자 안 "출처:" 문단은 번호 목록(제목 ↗ + 도메인)으로 바꾼다. 원문 본문 문자열은 바꾸지 않는다(표시 단계 변환).
12. **목차**: h2만, 3개 이상일 때. 클릭하면 머리 아래 16px 여백을 두고 이동.
13. **링크**: `rel="nofollow ugc noopener noreferrer"` 유지. 밑줄은 옅게, 출처 목록에서는 밑줄 없이 굵게.

## 9. 문구 규칙

- 해요체, 문장은 짧게. 기존 화면의 "~습니다" 안내문을 해요체로 맞출지는 사용자 결정 대기(handoff 질문 1). 맞추더라도 운영 안내의 법적 문장은 의미를 바꾸지 않고, 편집 글 **본문**은 승인본이므로 바꾸지 않는다.
- 고정 단어: 질문 / 공유 / 자유, 답 기다림 / 답변 n / 댓글 n, 공개 / 확인 중 / 공개 보류, 편집자 보충, 출처와 확인, "2017년 10월 카톡 기록".
- 시각: 1시간 안 "n분 전", 하루 안 "n시간 전", 7일 안 "n일 전", 그 밖 "10월 3일", 올해가 아니면 "2025년 10월 3일". 편집 자료의 시기는 원천 기간 문자열 그대로("2018년 11월 ~ 2018년 12월").
- 개수: "공개 글 330개", "검색 결과 8개". 비공개 글을 세지 않는다.
- 금지: "준비 중"을 큰 글씨로, 같은 고지 반복, "검증됨·인증" 같은 표현(정확성 인증 목록이 아님), 대화 원문 인용.
- 접근 이름(테스트가 쓰는 이름)은 유지: "글 쓰기", "검색어 지우기", "모든 조건 지우기", "전체 글 보기", "글 신고·삭제 요청", "로그인", "회원가입", "내 글", "수정", 목적 칩 "질문"·"공유"·"자유".

## 11. 접근성·움직임

- 대비: 본문·메타 4.5:1 이상(§5 표, 측정값). 상태는 색 + 단어.
- 키보드: 건너뛰기 링크 유지, `/`로 검색칸, 코드·표 상자는 `tabindex=0`로 가로 스크롤 가능, 시트는 Esc로 닫고 연 버튼으로 초점 복귀.
- 목록 줄 전체 링크는 제목 링크 하나로 만들고(가상 영역), 주제 링크는 그 위에 따로 누를 수 있게 한다(중첩 링크 금지).
- 펼침은 `aria-expanded`, 선택은 `aria-pressed`/`aria-current`로만 표현.
- 전환 150ms, 스켈레톤 반짝임만. `prefers-reduced-motion`이면 없음. 로고 움직임은 기존 규칙 그대로.
