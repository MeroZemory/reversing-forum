**탁상 추적: 합성 상황이며 실행 결과가 아니다.**

1. **본문 불변, 근거만 변경:** 공개 해시 h와 승인 묶음 g1이 유지된 작업에서 권리 근거를 보류하여 g2가 된다. L107·117에 따라 사이트 DB에서 이전 승인·대기 작업을 무효화하고 관련 글을 비공개로 전환한다. g1의 캐시·늦은 Jev 응답·게시 요청은 공개 권한이 되지 않는다. 최신 상태를 확인할 수 없어도 보류한다. 이미 전송된 입력의 회수를 보장하지 않고 후속 처리·영향을 기록한다. W08/W09의 실제 시험이 남는다.

2. **다른 후보 ID로 재등장:** 철회한 C1의 Q/A에 반박이 추가되어 모델이 임시 C2를 만든다. 임시 ID는 게시 식별자가 아니며, 편집자는 질문·논점·근거 대응으로 기존 영속 후보와 연결한다. 새 영속 ID나 의도적 분할도 문제의 원본 근거에 남은 억제 기록을 우회할 수 없다. 대응이 불명확하면 보류한다. 다른 날의 실제 반복은 별도 사례로 남길 수 있지만 자동 재공개 근거는 아니다. D04로 확인한다.

3. **철회 중 장애:** 억제 기록의 첫 쓰기 뒤 커밋 전에 중단되면 철회·승인 무효화·`posts` 전환 전체가 롤백된다. 기존 공개 상태가 남을 수 있으므로 철회 성공으로 처리하지 않고 재시도해야 한다. 커밋 후 응답만 유실되면 이미 비공개이며 재요청도 현재 상태를 반환한다. 늦은 Jev와 게시 경쟁은 최신 상태 검사로 차단해야 한다. 완료된 철회 이후의 새 조회·댓글·사이트맵·통제하는 캐시 노출은 W09/W06으로 시험한다. 취소·캐시 정리를 트랜잭션 밖에서 한다는 이유로 새 요청의 공개를 허용하지 않는다.

4. **틀린 제안과 반박 보존:** 제안 뒤 반박만 있고 성공 보고가 없으면 실제 질문·제안·반박을 공유 글에 남긴다. L77–83·89·93·101과 E03/E08은 당시 제안·상충과 현재 문서 확인·상충을 별도로 표시하고, 편집자가 추가한 설명·예제를 당시 답변과 구분한다. 독립 기술 설명도 별도 출처 유형이며 가상 문답을 붙이지 않는다. 최종본은 xhigh와 나머지 공개 조건을 모두 거친다. 현재 정답과 다르다는 이유만으로 과거의 유용한 논쟁을 삭제하거나 성공 사례로 바꾸는 경로는 요구되지 않는다.

처리 근거·제공자 계약과 실제 상한·계정 접근·표본 품질은 L51·57·115와 단계별 검증의 미확정 사항이다. 계획에 보류·중단 조건이 있으므로 이를 새 계획 blocker로 재명명하지 않는다. 로컬 첫 배치, 운영자 한 명, 기존 DB·인증·표시 계층이라는 범위도 유지한다. 현행 `createPost`가 Jev 반환 상태를 바로 반영하는 코드와 달리, L109는 편집 초안의 별도 비공개 등록·검토·공개 경로를 명시한다.
