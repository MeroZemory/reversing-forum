# 전체 자료 처리의 구현 기준

2026-10-02 사용자 결정에 따라 계획의 첫 소수 게시 이후에도 전체 백업 처리를 이어간다. 고정된 계획 검수본은 보존한다.

- 자료 가공 배치에 별도로 Codex CLI 주간 한도의 약 10%를 배정한다. 다른 세션의 사용량이 섞인 계정 전체 사용률 증분을 이 작업의 소모량으로 계산하지 않는다. 별도 LLM 유료 API를 사용하지 않는다.
- Jev는 전체 10달러 이내에서 필요할 때 사용한다. 최종 공개본마다 통과 결과가 있어야 한다. 여러 최종본을 한 요청에서 검사할 때 한 글의 통과를 다른 글의 통과로 간주하지 않는다.
- 한국어 작성자 표시는 ‘자료편집’과 운영 계정 배지로 구분한다. 고정 계정 식별자는 표시 언어에 영향을 받지 않는다. 다른 언어는 같은 역할의 표시명만 바꾼다. 실제 운영자가 편집과 승인을 책임진다.
- 전체 처리는 모든 원본 범위의 포함과 중복 대응, 유의미한 질문·응답 및 지식 후보의 처리 상태를 기록하는 것을 뜻한다. 원본 대화 아카이브, 실제 회원인 것처럼 꾸민 계정·댓글, 의미 없는 발언을 게시하지 않는다.

## 로컬 원자료 처리

사용자가 공개 카톡방의 백업으로 제공한 다섯 파일을 기술 정보의 편집·정리에 필요한 범위에서 로컬로 파싱한다. 공개방이라는 전제는 사용자 설명이며, 모든 과거 시기의 입장 제한을 독립 확인한 사실은 아니다. 개인별 활동 평가나 닉네임 변경을 이용한 신원 통합을 하지 않는다. 개인정보 처리의 정당한 이익과 공개 당시 객관적으로 인정되는 이용 범위는 기존 법률 검토의 조건을 적용한다. 원자료는 공개하지 않고 프로젝트의 무시된 `data/` 안에만 작업 결과를 보관한다.

원본의 로컬 파싱 권한과 외부 AI 전달·웹 공개 권한을 구분한다. 외부 작업자는 최소화된 기술 자료만 받고 원본 백업·닉네임 대응·인증정보를 읽지 않는다. 정규식 검사가 익명화를 보증하지 않는다. 기술적 의미에 필요 없는 연락처·계정·개인 경험·개인 링크·비밀값을 제외하고 예외를 보류한다. 개인정보 또는 창작적 표현이 남은 사례는 별도 근거가 확인되지 않으면 공개하지 않는다. 사실과 기술적 방법의 독립적인 설명을 우선하며, 과거 제안의 사실 여부와 현재 확인 여부를 구분한다.

표시하는 처리·권리 근거는 실제 확인한 범위에만 적용한다. 모델 출력이나 사용자 작업 지시를 제삼자의 동의로 기록하지 않는다. 표본 확인 없이 이름 치환만으로 전체 외부 전달을 허용하지 않는다.

## 구현 확인 지점

1. 합성 테스트 후 실제 파일의 형식별 파싱 개수·미해석 범위·처리 시간을 확인한다.
2. 전체 입력의 대응표를 만들고 최소화한 표본으로 후보 추출·편집 결과와 실행별 토큰을 확인한다.
3. 실제 세션의 편집 승인·최종 Jev·게시·철회와 화면 표시를 연결한다.
4. 첫 공개 글의 읽기·검색·댓글을 확인한 후 나머지 적합한 후보를 처리한다. 남은 보류·누락·예산 중단은 공개 글 개수와 분리하여 보고한다.

새로운 중대한 문제가 없으면 구현 전체를 매번 최고 추론 설정으로 재검수하지 않는다. 변경한 경계의 실제 테스트와 결과를 우선한다.

## 사용량 측정

자료 가공의 호출별 입력·캐시 입력·출력 토큰을 비공개 기록과 별도 SQLite 장부에 저장한다. 캐시 입력은 전체 입력의 일부이며 추론 토큰도 출력에 포함되어 있으면 다시 더하지 않는다. 사용량을 확인하지 못한 실패 호출은 예약분을 유지한다. 실행 전 예약은 같은 장부에서 원자적으로 처리한다. 계정 전체 사용률은 계정 변경이나 한도 소진을 확인하는 용도로만 쓴다.

주간 모수에는 사용자 공개 측정을 참고한다. 2026년 9월 공개된 Pro 20x 기록에서는 두 Sol 사용 구간의 토큰을 당시 API 가격으로 환산하고, 관측한 주간 사용률로 역산한 값이 한 주당 약 1,666~1,810달러였다. 이는 실제 구독 비용이나 보장된 주간 한도가 아닌 비교용 환산값이다. [공개 측정과 방법](https://github.com/openai/codex/issues/43222#issuecomment-5590186765)

같은 글의 다른 사용자 기록에는 캐시 비율 약 98%인 Sol 작업에서 약 14억 입력 토큰을 사용한 주간 사례도 있다. 다른 컴퓨터의 사용이 빠졌다는 한계가 명시되어 있으므로 원시 토큰 총량을 보편적인 한도로 삼지 않는다. [토큰·캐시·한도 기록](https://github.com/openai/codex/issues/43222#issuecomment-5571338056)

현재 모델의 입력·캐시·출력별 가중치는 상대적인 작업량을 계산하는 데만 사용한다. 공식 모델별 환산표는 주간 총량의 근거로 사용하지 않는다. [모델별 환산표](https://learn.chatgpt.com/docs/pricing)

당시 API 가격 환산값을 현재 작업의 다른 가중치와 직접 비교하지 않는다. 공개 토큰 관측을 우리 비교 단위로 다시 환산한다. 신규 입력·캐시 입력·출력 백만 토큰당 각각 2·0.1·10을 적용하면, 두 Sol 관측은 `(36×2 + 1,411×0.1 + 5×10) ÷ 1.00 = 263.10`, `(28.1×2 + 1,292.9×0.1 + 4.1×10) ÷ 0.90 = 262.43`이다. 다른 기기의 사용이 빠져 있어 실제 주간 모수의 하한에 가까운 참고값이며, 6.1 모델에도 같은 관계가 성립한다고 확정할 수 없다.

이번 실행의 운영 추정 범위는 같은 비교 단위로 200~905.18이며 중심값은 262.43이다. 200은 낮은 공개 토큰 관측값에 여유를 두어 정한 값이다. 905.18은 다른 공개 측정의 당시 가격 환산값 1,810.36에 가능한 환산 비율의 큰 값 0.5를 적용한 참고 상한이며 정확한 한도가 아니다. 실행 제한에는 낮은 운영 추정값 200의 10%를 적용한다. 달러 모양의 비교 단위는 실제 API 결제액을 뜻하지 않는다. 설정과 근거는 무시된 `data/chat-pipeline/model-budget.json`에 보관한다.

세션 전체의 참고 집계는 명시한 스레드와 그 하위 작업만 선택한다. 같은 프로젝트 경로라는 이유로 다른 세션을 포함하지 않는다. 호출별 기록과 세션 로그의 누적 토큰을 중복 합산하지 않으며, 지원하지 않는 모델의 기록은 미확인 항목으로 남긴다.

## 실제 처리 상태

다섯 백업의 원본 범위와 중복 대응표를 로컬에 만들었다. 현재 기준으로 525,084개 메시지에 작업 범위를 연결했고, 17,524개는 민감정보 의심 또는 파싱 경계 문제 등으로 보류했다. 미해석 범위 3,588개도 원본 위치와 함께 보존한다. 범위 대응이 끝났다는 사실은 의미 검토나 공개 게시가 끝났다는 뜻이 아니다.

첫 편집 배치에서는 20개 후보 중 독립 Sol 검토를 통과한 8개를 실제 편집 세션과 글별 Jev 검수로 공개했다. 웹 게시일과 과거 기록 기간을 분리하고, 실제 회원의 댓글이나 활동량을 생성하지 않았다. 헤드리스로 데스크톱·390px 화면을 확인했으며 비공개 근거 식별자 노출, 가로 넘침, 콘솔 오류가 없었다. 나머지 자료 가공은 진행 중이다.

관련성 예비 선별은 Jev를 사용했지만 이번 입력의 99.7%를 후속 대상으로 남겼다. 같은 선별을 반복하지 않는다. 정상적인 예비 분류의 불확실성은 Luna의 직접 의미 검토로 해소할 수 있고, 실제 호출 오류는 별도 상태로 보존한다. 공개본의 최종 Jev 검수는 이 예비 선별과 별개다.

모델의 범위 겹침·분류 누락은 코드로 추적하고 확인이 필요한 상태에 남긴다. 숫자 범위를 보정했다는 이유로 원래 모델이 전 항목을 의미 검토했다고 기록하지 않는다. 유효한 후보를 보존해 편집·독립 대조를 이어가며, 원래 출력과 복구 보고서는 비공개로 보관한다.
