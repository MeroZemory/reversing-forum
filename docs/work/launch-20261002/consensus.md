# Reversing All 공개 운영 구현 합의

2026년 10월 2일 사용자가 사이트 구성 개편, 의미 중복과 스팸 방지, 전체 제공 기록의 가공과 적격 자료 게시, Cloudflare 임시 하위 도메인 배포를 승인했습니다. Sol 6.1 max와 Astra max가 각각 독립 검토한 뒤 상대 검토안과 조정안을 읽고 모두 아래 계약에 합의했습니다. 별도 게시판과 작성자 분류 절차를 늘리지 않는 첫 구현입니다.

## 글을 찾는 두 입구

‘최신 글’은 현재의 참여를, ‘자료 길잡이’는 다시 읽을 정보를 찾는 입구입니다. 글 주소, 작성, 댓글, 검색은 공유합니다. 운영자가 공개 글을 길잡이에 연결하며 작성자는 기존 질문·공유·자유 중 목적을 선택합니다. 회원과 편집 자료에 같은 수록 기준을 적용합니다. 수록이나 운영 계정 표시는 정확성 인증이 아닙니다.

주제·적용 조건·과정·배울 점·한계를 원래 대화 없이 이해할 수 있는 글을 연결합니다. 부분 답변, 잘못된 접근, 의견도 성격과 한계를 설명하면 포함할 수 있습니다. 처음에는 실제 공개 글로 채울 수 있는 작은 길잡이를 만듭니다. 태그와 과거 기록 기간은 글의 목적 및 웹 게시일과 구별합니다.

시작 시점의 공개 글 15개는 모두 편집 글입니다. 회원 활동을 만들어 채우지 않습니다. 편집 자료가 많아지면 홈에서 짧은 제목 묶음으로 연결하고 실제 회원 글과 댓글 참여를 함께 보여 줍니다. 각 글은 공통 검색과 전체 자료 목록에서 계속 찾을 수 있어야 합니다.

## 새 기여를 기준으로 중복 판정

같은 요청의 재전송과 정확 복제를 먼저 확인하고, 복제 구간과 임베딩으로 공개 글 후보를 찾습니다. 문서 및 모든 본문 블록에서 찾은 후보를 합쳐 여러 기존 글의 짜깁기도 비교합니다. 블록에는 제목·소제목·환경 문맥과 원래 위치를 연결하며 겹치는 구간을 두 번 계산하지 않습니다.

차단 대상은 의미 있는 새 정보가 없는 재표현, 재배열, 짜깁기 및 무관한 내용 덧붙임입니다. 새 조건, 정정, 새 근거, 다른 해법, 새로운 종합 설명은 보호합니다. 한 구간의 최고 유사도나 평균 점수만으로 차단하지 않습니다. 대응하는 기존 내용과 새 기여 판단의 근거가 필요합니다.

실제 Jev의 독립 질문으로 조건·근거·정정·기존 답의 충족 여부를 비교하고 애매한 사례에는 실제 LLM을 사용합니다. 점수와 confidence를 한국어 리버싱 정확도로 해석하지 않습니다. 불확실, 설정 누락, 호출 오류, 예산 초과는 비공개 검토로 처리합니다. 임베딩은 로컬 CPU에서 비양자화 모델을 사용하며 LLM은 도구 사용을 차단한 Codex CLI 호출로 연결합니다.

공개 후보와 연관 글은 현재 공개된 글만 대상으로 합니다. 다른 회원의 비공개 글 존재·제목·내용·유사도를 노출하지 않습니다. 자기 글 수정은 자기 이전 판본을 중복 비교에서 제외할 뿐, 변경된 최종본의 공개 전 검수를 생략하지 않습니다.

같은 입력의 캐시도 공개 비교 자료가 바뀌면 다시 확인합니다. 동시 요청과 배치 내부의 중복을 막기 위해 공개 처리를 조정하고 게시 직전에 비교 자료 변경을 확인합니다. 편집 산출물의 안정적인 식별자는 재게시를 막지만 출처가 겹친다는 이유만으로 서로 다른 논점을 차단하지 않습니다.

## 스팸과 공개 조건

기존 글·댓글 작성 간격과 분당 제한을 유지합니다. 같은 요청의 처리 공유, 반복 본문, 서버 전체 동시 호출 및 예산 제한은 유료 검수 전에 적용합니다. 같은 공식 자료 링크만으로 정상 글을 차단하지 않습니다. 의미 중복 판정과 계정 제재는 구별합니다.

일반 글은 비공개 등록 후 최소 Jev 검수와 의미 중복 확인을 통과해야 공개합니다. 편집 자료는 같은 최종본에 대한 출처·근거·권리·개인정보 확인, 지정된 실제 Sol 6.1 xhigh 독립 검토, 실제 운영자 세션의 승인 및 실제 최종 Jev 결과를 모두 유지합니다. 원본 카톡, 가상 회원·댓글·활동량은 공개하지 않습니다.

전체 제공 기록의 처리 결과를 추적하되, 개인정보·권리 불명·유해 자료는 보류합니다. 원본 위치 대응과 분류 완료를 의미 검토나 공개 적격 확인으로 취급하지 않습니다. 자료 가공의 Jev 상한은 10달러, Codex 사용량은 기존 실행별 추산 한도인 20 proxy 단위 이내로 유지합니다. 이 단위는 실제 API 지출이나 정확한 주간 사용률이 아닙니다.

## 배포 전 확인

- 실제 재표현·재배열·짜깁기·블록 경계 변경을 차단하고 새 조건·정정·근거·해법을 허용하는 어려운 표본을 확인합니다. 후보 검색과 최종 판정의 오류를 구분합니다.
- 재시도와 동시 요청에서 중복 저장·중복 과금·중복 공개가 없어야 합니다. 검수 오류와 예산 초과 때 비공개를 유지합니다.
- 기존 글 주소와 댓글, 세션 권한, 목록·자료 길잡이·로그인 후 복귀 문맥을 보존합니다. 공개 응답에 비공개 근거나 인증 값이 없어야 합니다.
- 타입 검사, 관련 테스트, 빌드, 헤드리스 화면·작성·댓글 검증을 완료합니다. 임시 주소에서도 실제 세션과 영속 저장을 확인합니다.

임시 배포는 현재 Windows PC의 Node 서버와 SQLite를 Cloudflare Tunnel로 연결하는 안입니다. PC와 프로세스가 실행 중이어야 서비스됩니다. 도메인은 `reversing.agentryx-ai.com`이며 원본·작업 DB·비밀값은 배포 산출물에서 제외합니다. 토큰의 터널 생성 권한과 실제 외부 연결은 별도 확인 대상입니다.

## 참고한 구현 근거

[NeMo Curator](https://docs.nvidia.com/nemo/curator/latest/curate-text/process-data/deduplication)는 정확·근사·의미 중복 탐색을 구별합니다. [Winnowing 논문](https://theory.stanford.edu/~aiken/publications/papers/sigmod03.pdf)은 위치를 보존하는 부분 복제 탐색의 참고입니다. 두 자료가 포럼의 새 기여 기준이나 차단 정확도를 보장하지는 않습니다.

[Elastic의 semantic_text](https://www.elastic.co/docs/reference/elasticsearch/mapping-reference/semantic-text-reference)는 긴 글을 블록으로 검색합니다. [Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)은 문맥 없는 블록의 검색 한계를 설명합니다. 이 포럼의 전체 기여 비교와 후보 합집합은 이러한 검색 사례를 바탕으로 정한 제품 판단입니다.

[Typesafe primitives](https://docs.typesafe.ai/primitives)는 서로 독립적인 사용자 지정 질문을 지원합니다. 실제 도메인 표본에서 충분성을 확인해야 합니다. [OWASP API4](https://api-security.owasp.org/editions/2023/en/0xa4-unrestricted-resource-consumption/)는 요청·자원·외부 서비스 비용 제한의 근거입니다.

[Cloudflare 터널 API 안내](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/get-started/create-remote-tunnel-api/)에 따라 전용 터널과 단일 하위 도메인만 연결합니다. 기존 다른 서비스의 DNS나 터널을 덮어쓰지 않습니다.
